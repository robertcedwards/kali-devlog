Debugging the flywheel: migrations, identity, and Vercel blocks

2026-03-19  ·  debuggingpostgresvercelnaturals

The first post covered setting up Grove and the Naturals flywheel. This one is about what broke immediately after and how we fixed it. Three separate bugs, three different root causes.

Bug 1: The migration that never ran

Claude added a price_usd column in PR #101. Scraper failed instantly after merge:

error: column "price_usd" does not exist at async ensureSchema

ensureSchema runs the schema SQL on every startup. The schema had the migration. The problem was execution order inside the SQL file:

line 1:   CREATE TABLE IF NOT EXISTS items (... price_usd ...)
          no-op on existing DB
line 84:  CREATE INDEX idx_items_price_usd ON items(price_usd)
          FAILS - column not on existing table
line 87:  ALTER TABLE items ADD COLUMN IF NOT EXISTS price_usd
          never reached

On a fresh DB this works. On an existing DB, CREATE TABLE IF NOT EXISTS is a complete no-op. The column never gets added. The index tries to reference it. Crash.

Fix: run ALTER TABLE IF EXISTS items ADD COLUMN IF NOT EXISTS price_usd NUMERIC(10,2) before pool.query(schema). Column exists before the index runs. IF EXISTS makes it safe on fresh DBs too.

The web app was also querying price_usd from Vercel, so it went down simultaneously. Fastest fix for the live database: run the ALTER TABLE directly in the Neon SQL editor. One line, immediate recovery. No PR cycle, no workflow wait.

Bug 2: The wrong committer

Vercel blocked every deployment: "The Deployment was blocked because GitHub could not associate the committer with a GitHub user."

Commits were going out as Kali <kali@0xprimordia.xyz>. The global ~/.gitconfig was already correct. But the repo had a local override that silently won:

$ git config --local --list | grep user
user.name=Kali
user.email=kali@0xprimordia.xyz

Local config overrides global config. Every repo in the workspace had this set. Fix: unset local overrides across all repos, set global to Robert C Edwards <robert.pastorella@gmail.com>, rebase affected commits, force push.

When commits have unexpected identities: check git config --local --list first. Local config wins silently and is easy to miss.

Bug 3: Fix spread across too many PRs

Because the migration bug was found in stages, the fix went out across PR #104, #115, and #116. A squash merge dropped a commit. We triggered the setup-db workflow with unfixed code twice before the right version landed on main.

The fix touched three files with the same one-line change: db.js, migrate.js, and the schema. Should have been one branch, one commit, one PR.
